# 测试报告导出规范

> 步骤9使用。每个菜单的每种测试类型，测试PASSED后必须生成一份Markdown测试报告。

## 文件路径规范

```
{project_root}/{testcases_dir}/测试报告/{菜单名}/{测试类型}.md
```

示例：
```
testcases/综合理财平台6.0/基金代销/测试报告/
  ├─ 基金代销历史冻结解冻流水查询\
  │   ├─ 条件重置测试报告.md
  │   ├─ 单条件查询测试报告.md
  │   └─ 多条件查询测试报告.md
  └─ ...
```

## 报告内容模板

```markdown
# {菜单名} - {测试类型} 测试报告

## 测试基本信息

| 项目 | 内容 |
|------|------|
| 菜单名称 | {菜单名} |
| 测试类型 | {测试类型} |
| 测试文件 | test_xxx.py |
| 执行时间 | {YYYY-MM-DD HH:MM} |
| 测试结果 | ✅ PASSED / ❌ FAILED |
| 执行耗时 | {N}s |

## 预埋数据

| 表名 | 字段 | 值 | 说明 |
|------|------|----|------|
| ui_bc.tbtainfo | ta_code | JS | TA代码 |
| ... | ... | ... | ... |

（从数据预埋SQL中提取，列出所有INSERT/REPLACE语句的关键字段）

## 测试步骤与断言

| 步骤 | 操作 | 断言条件 | 预期结果 |
|------|------|----------|----------|
| 1 | 打开菜单「{菜单名}」 | 页面标题可见 | ✅ |
| 2 | 选择客户标识类型=0:入账账号 | _select_dropdown_by_label | ✅ |
| ... | | | |

## 断言依据

列出每个断言的来源：

- **查询结果行数 > 0**：依据预埋SQL中 INSERT 的记录数
- **重置后字段为空**：依据 HUI 重置按钮行为——触发后所有 .h-form-item input 值清空为 ""
- **详情弹窗字段值**：依据预埋SQL中对应字段的值（通过input.value读取）
```

## 生成规则

1. **预埋数据** 从测试文件中的 `PRESET_SQL` 变量路径对应的 `.sql` 文件提取
2. **测试步骤** 从测试函数的操作序列整理，每步对应一个断言
3. **断言依据** 说明每个 `assert` 的判断标准和数据来源
4. **一个测试函数 = 一份报告文件**
5. 测试 PASSED 后立即生成，不等所有类型完成
6. 已有报告文件则覆盖更新

## 何时生成

- **测试 PASSED 后立即生成**
- 如果之前已有报告文件，**覆盖更新**（保持最新通过状态）
- 报告文件是交付物的一部分，和测试代码一起交给用户
